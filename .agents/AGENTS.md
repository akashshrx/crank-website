# Project Customization Rules — Glide Website

- The product name is **Glide** (formerly Crank/Caret). Avoid using "Crank" or "Caret" in code, text copy, or document filenames.
- The GitHub repository name is `glide-website`.
- The primary download file target is `Glide_macOS.dmg`, but every Download button MUST link to `https://black-yak.spcf.app/download/mac` (the Glide backend's counting redirect, which 302s to the .dmg). Never point buttons at the .dmg directly — that would silently stop download tracking on the admin portal.
- The official branding logos for Glide are:
  - Dark logo: `logo_dark.png` (used in the header navigation bar).
  - White logo: `logo_white.png` (used in the dock footer layout).

- **`privacy.html` section 3.5 "Product Analytics" MUST survive any edit to that page.** The shipped macOS app (build 401+) collects product analytics by default with no user-facing opt-out, so this section is the only place that is disclosed. It is queued and unpublished: the live site is frozen on the Aug 3 build because Netlify deploys are blocked on account credits, and everything on `main` publishes automatically the moment credits return. If you rewrite or regenerate `privacy.html`, carry 3.5 across verbatim and keep Data Security numbered 3.6. Do not soften it, and do not describe analytics as optional or as something users can switch off, because today they cannot.

### Development Guidelines

- **Cursive Font Margin Adjustment**: The `Caveat` font (used for `.caveat-highlight` or similar classes) has cursive styling where letters tilt to the right. Always apply a right margin (e.g., `margin-right: 0.1em;`) or padding on these span tags to prevent cursive characters from overlapping the normal characters that follow.
- **GSAP Parent Wrapper Animation**: To avoid visual elements overlapping with scrolling grids during GSAP pinning timelines, animate the parent container (e.g. `.questions-title-side`) rather than the text and children elements separately. This ensures all components fade out and translate in perfect synchronicity.
- **CSS Specificity with SVG Diagrams**: The SVG line-art diagrams (e.g., inside `.bento-diagram`) are styled globally. When introducing high-fidelity details (like thin wireframes, cursor paths, or small circles), override the global settings with explicit classes (e.g. `.window-btn`, `.cursor-path`) using `!important`. Always add `:not(.accent-line)` exclusions to hover state declarations so they don't override the glowing filter bloom on accent lines.
- **CSS Apple Keyboard replica styling**: When rendering keyboard keys, use specific classes (e.g., `.mac-key-cap`) to avoid bleeding styles from page-wide generic `.key-cap` buttons. Use `white-space: nowrap;` on text labels to prevent multi-line wrapping of longer words like "command" from stretching the keys.
- **Footer Text Contrast**: The site theme shifts based on time of day. To ensure the footer navigation links and copyrights are readable on both day (light blue) and night (dark blue) WebGL canvases, style them as white text (`#ffffff`) with a drop shadow (`text-shadow: 0 1px 3px rgba(0, 0, 0, 0.4)`). Avoid dark/transparent opacities.
- **Branding Check Rules (MANDATORY)**: Every time you edit the UI or create new pages, refer to these brand guidelines. Specifically, the webpage design is built around a dark atmospheric theme with deep blue/space night WebGL sky gradients. As such, all main texts (titles, questions, headers, and paragraphs) must use white (`#ffffff`) or subtle off-white (`var(--text-subtle)`) text colors. Dark charcoal/black (`#121210` or `#000000`) must ONLY be used on solid white component backgrounds (such as CTA buttons) to keep the layout highly legible. Main headers must use the Figtree sans-serif font (`var(--font-sans)`) rather than serif.
- **Third-Party Company Logos (MANDATORY)**: When embedding icons from other companies (e.g. Chrome, Safari, Apple Notes, Acrobat, Figma, Notion, Slack, Linear, GitHub, HubSpot, etc.), never use hand-drawn approximations, simplified circle-based drafts, or custom reconstructions of those logos as they render deformed and malformed. Always retrieve the **100% official vector path data** (using assets from developer resources, upload.wikimedia.org, or official repositories like simple-icons/browser-logos) to ensure precise brand geometry, layout, and colors.
- **No Auto-Deploy / Git Push Rule (MANDATORY)**: Do **NOT** automatically `git push` to GitHub or deploy to the live domain just because code edits or file changes were made. Pushing to GitHub triggers Netlify auto-deploys which consume build minutes. Always test and verify changes locally. Only execute `git push` when the user explicitly instructs to deploy/push or confirms that a completed batch of changes is ready to be published.
- **Clickable Links Requirement (MANDATORY)**: Whenever you build, update, or create files or pages, ALWAYS output clear, clickable markdown links for the active local dev server ([http://localhost:8080](http://localhost:8080)), the local file paths (`file:///...`), and the official live domain ([https://justglide.app](https://justglide.app)).
